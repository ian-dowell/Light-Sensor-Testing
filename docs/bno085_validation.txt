BNO085 troubleshooting and diagnostic validation
Date: 2026-10-16 (America/Chicago)

Hardware finding:
The user reports red -> 3.3 V, black -> GND, blue -> seventh header pin
on the I2C side, with P0/P1 unconnected. Adafruit #4754 defaults to I2C
in that configuration. The existing application expects UART-RVC.
Required correction: P0 -> 3V3, P1 remains LOW by its default pulldown
with its solder jumper open, verify blue -> GPIO20, then power-cycle.
No original four-sensor sketch source was changed.

Software checks:
- Independent review of the original UART configuration, polling, and
  local Adafruit_BNO08x_RVC 1.0.2 implementation found no evident cause
  for persistent absence with correctly configured hardware.
- Five strict C++11 host parser tests passed: signed/chunked decoding,
  noise/back-to-back frames, checksum failure preserving the last good
  reading, truncated-frame recovery, and payload headers/long noise.
- Optional AddressSanitizer execution stalled without output and did
  not provide a sanitizer result. The ordinary host tests passed.
- Standalone diagnostic compiled for both ESP32-C6 console settings.
  Arduino CLI 1.5.1, ESP32 core 3.3.12, warnings=all.
  No sensor libraries required. Build logs show no warnings/errors.
